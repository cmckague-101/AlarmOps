## Overall impression

Visual system is disciplined and unusually product-specific. Core gap is not styling. FireOps presents records well but does little to reduce dispatcher workload once fleet size and issue volume grow.

## What's working

- Status is redundant in useful ways: text, color, icons, counts, and explicit issue language. Users do not need color alone.
- Drawers have focus trapping, Escape close, focus return, labeled dialogs, error summaries, and mobile full-width behavior. This is careful production work.
- Responsive choices preserve operational facts. Mobile keeps issue counts, uses 44px targets, 16px form text, bottom navigation, safe areas, and sticky submit actions.

## Priority issues

### [P1] Dashboard is a feed, not a triage tool

**Why it matters.** “Needed actions” mixes open issues with maintenance-state vehicles, can represent one underlying problem twice, and offers no priority, age, unit, or ownership sort. Dispatchers must inspect rows one by one to decide what threatens readiness.

**Fix.** Define one actionable work-item model. Group by “Blocks deployment,” “Due soon,” and “Monitor.” Add unit, owner, age, and next action. Deduplicate vehicle state when an open issue already explains it.

**Suggested command.** `/impeccable shape`

### [P1] High-impact state changes commit too easily

**Why it matters.** Selecting “Out of service,” changing assignee, or clearing assignment writes immediately. Seven-second undo helps, but a missed toast can alter deployment readiness or crew ownership.

**Fix.** Keep immediate changes for low-risk states. Require a short reason and explicit confirmation for “Out of service,” clearing an active assignment, and reassignment. Keep undo and activity history.

**Suggested command.** `/impeccable harden`

### [P2] Expert workflows stop at search and one status filter

**Why it matters.** Real fleets need repeated scans across readiness, issue priority, assignment, expiring documents, and unit type. One search field and one filter force repetitive manual inspection. No bulk path exists.

**Fix.** Add sortable fields, composable filters, saved views, bulk assignment/status actions, and keyboard focus for search. Keep novice defaults quiet.

**Suggested command.** `/impeccable layout`

### [P2] Add-vehicle form reveals too much optional work

**Why it matters.** Six upload controls, registration fields, and notes appear in one long second section. This creates three cognitive-load failures: chunking, minimal choices, and progressive disclosure.

**Fix.** Make vehicle identity first save. Collapse “Documents and registration” behind an optional step or add-documents-after-save path. Show completion status in vehicle detail.

**Suggested command.** `/impeccable distill`

## Persona red flags

**Alex, power user.** Can search quickly, but cannot sort by issue count, batch update units, save a readiness view, or use keyboard accelerators. Repeated one-record drawers become bottleneck well before 100 vehicles.

**Sam, accessibility-dependent user.** Core controls, focus rings, dialog trapping, text labels, and non-color status cues are strong. Main red flag is workflow, not markup: immediate select-triggered status saves give keyboard and screen-reader users no review checkpoint for consequential changes.

**Casey, distracted mobile user.** Bottom navigation, full-screen drawers, sticky submit, and touch sizes work. Add Vehicle remains long, upload-heavy, and interruption-prone. Draft state is local component state and disappears if drawer closes or page reloads.
