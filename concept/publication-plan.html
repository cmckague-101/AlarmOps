02 · Current code audit

What exists—and what does not

Strengths

  • Broad, coherent operational workflows and dark visual system.
  • Expo supports one native codebase for iOS and Android.
  • TypeScript currently passes tsc --noEmit.
  • Reusable cards, buttons, headers, status badges, theme tokens.
  • Useful camera, document picker, PDF, sharing, maps, and local persistence prototypes.
  • Public NIFC incident and NWS alert adapters show viable integration direction.

Production blockers

  • No sign-in, session handling, password recovery, MFA, organization isolation, or real invitations.
  • Most records are flat JSON arrays in AsyncStorage; devices cannot share authoritative state.
  • Roles shown in UI are not enforced by server. Names and IDs such as Clint, FireCo, and master-1 are hard-coded.
  • Uploaded document URIs often point to temporary device cache, not durable private storage.
  • No test suite, CI pipeline, migrations, audit log, analytics, crash reporting, backups, or disaster recovery.
  • No push-notification package/service despite notification settings in UI.

Recommended stack

Data and identity

Supabase Pro: PostgreSQL, Auth, private Storage, Realtime, row-level security, backups. Good 50-user economics and fast implementation.

Use managed auth for email invitations, password reset, session rotation, and MFA. Keep authorization rules in database/API—not only React components.

API and jobs

Node.js + TypeScript service using Fastify or NestJS on Render, Fly.io, or Google Cloud Run. Worker handles OCR, QuickBooks sync, notifications, feed caching, virus scanning, PDF generation.

Clients receive only public base URL and short-lived access tokens. OAuth client secrets, AI keys, and refresh tokens stay server-side.

Applications

Expo/EAS for iOS/Android. Next.js on Vercel for desktop operations and administration.

Monorepo shares schemas, API client, permission constants, validation, and visual tokens—without forcing dense desktop pages into mobile layouts.

Reliability

Sentry for crashes, structured logs for API, uptime checks, product analytics with PostHog, transactional email with Postmark/Resend.

Nightly database backup, object lifecycle policy, tested restore, and operational runbook.

Offline field model

  1. Store normalized working data in SQLite, not AsyncStorage arrays.
  2. Write mutations to local outbox with UUID, organization ID, actor ID, version, and idempotency key.
  3. Sync over authenticated API when network returns; show Pending / Synced / Failed states.
  4. Use server timestamps and explicit conflict strategy. Never silently overwrite inspection, payroll, or qualification records.
  5. Copy captures into app-owned storage until upload succeeds; then retain server file ID and signed-view URL.

Account flow for first 50 users

  1. Platform operator creates organization and first protected owner account.
  2. Owner configures company name, logo, timezone, retention, enabled modules, and role templates.
  3. Owner invites by email. Invite is single-use, expiring, organization-bound, and logged.
  4. User verifies email, creates password/passkey, enrolls MFA if admin/finance, accepts Terms and Privacy Policy.
  5. Backend creates membership. Role permissions govern API and database access.
  6. Suspension revokes sessions immediately. Offboarding preserves legally required business records while removing access.
Initial registration recommendation: no public company sign-up. Keep invite-only onboarding through pilot. Add self-service company registration after billing, abuse prevention, tenant provisioning, and support processes work.

06 · APIs & systems

Connections needed for “all features working”

Core API

  • REST/JSON under /v1 with OpenAPI contract.
  • JWT auth, organization context, request IDs, rate limits.
  • Schema validation using Zod or generated OpenAPI types.
  • Idempotency keys for submissions, checkout, invoices, and webhooks.
  • Cursor pagination and server-side search.

Realtime + push

  • Supabase Realtime or WebSocket channels for chat/status.
  • Expo Push Service for initial mobile delivery; APNs/FCM credentials via EAS.
  • Store multiple device tokens per user; prune invalid tokens.
  • Notification preferences enforced server-side.
  • Email fallback for invites, security events, and critical workflows.

Files + OCR

  • Private object buckets with signed upload/download URLs.
  • Virus scan, MIME and size checks, thumbnail/PDF preview jobs.
  • AWS Textract, Azure Document Intelligence, or Google Document AI for payroll/invoice/receipt extraction.
  • Schema-constrained normalization and confidence per field.
  • Human review before finance or payroll export.

Maps + fire data

  • NIFC/WFIGS ArcGIS feeds and NICC IMSR transformer/cache.
  • NWS API with descriptive User-Agent and server caching.
  • NASA FIRMS API using server-held MAP_KEY.
  • Mapbox or Google Maps for web/native base maps and geocoding.
  • Motive API only after account approval and scope confirmation.

QuickBooks Online

  • Intuit OAuth 2.0 connect/callback/disconnect routes.
  • Encrypted token storage and proactive refresh.
  • Company realm, customer/vendor/item/account mappings.
  • Webhook verification and replay-safe event processing.
  • Sandbox certification tests before production keys.

Operational tooling

  • Sentry errors and performance traces.
  • PostHog privacy-aware product analytics.
  • Postmark/Resend transactional email.
  • UptimeRobot/Better Stack monitoring and alerts.
  • GitHub Actions: lint, typecheck, tests, builds, migration checks.

07 · Desktop & mobile

Do not stretch one mobile layout across every screen

Mobile field app

  • Keep Expo React Native.
  • Bottom navigation, camera capture, push, location, offline queue.
  • Large tap targets and fast one-handed workflows.
  • Limit dense administration and accounting tools.
  • Test low connectivity, process termination, upload resume, and old devices.

Desktop operations site

  • Build Next.js responsive console with sidebar navigation.
  • Tables, filters, bulk actions, split map/list layouts, keyboard navigation.
  • Best home for user administration, finance review, fleet planning, reports, integration setup, and moderation.
  • Deploy same API and authorization model; no separate business database.
Confirmed web blocker: current static Expo web export fails because IncidentMapScreen.tsx directly imports react-native-maps. Short-term fix: platform-specific IncidentMapScreen.native.tsx and IncidentMapScreen.web.tsx. Better long-term result: dedicated Next.js desktop map using Mapbox GL JS or Google Maps.

Code sharing target

  • Share: domain types, Zod schemas, API client, query keys, permission definitions, date/money formatters, design tokens, calculation functions.
  • Do not force-share: navigation shells, maps, complex desktop tables, drag/drop admin workflows, native camera and file adapters.
  • Use responsive breakpoints and max-width containers. Current two-column cards using fixed percentages need single-column behavior on narrow phones and wider desktop layouts.
  • Remove global orientation: portrait if supporting tablets; choose orientation by screen needs and test iPad/Android tablet.
08 · Code foundation

Changes before adding more screens

  1. Create monorepo: apps/mobile, apps/web, apps/api, packages/domain, packages/api-client, packages/ui-tokens.
  2. Replace component-owned demo arrays: repository/service hooks using TanStack Query. Server is source of truth; local cache is explicit.
  3. Centralize identity: AuthProvider, OrganizationProvider, useCurrentUser(), usePermissions(). Remove hard-coded actor/company values.
  4. Centralize permissions: generated permission constants shared with backend. UI hiding improves UX; API/RLS enforcement supplies security.
  5. Normalize domain models: IDs as UUIDs, ISO timestamps, enums, money in integer cents, organization IDs, created/updated actor IDs, record versions.
  6. File abstraction: records store backend file IDs and metadata, never temporary picker URIs as durable references.
  7. Forms: React Hook Form + Zod, field-level errors, date picker, accessible labels, server error mapping, submission locking.
  8. Testing: Vitest/Jest for domain logic, API tests against temporary Postgres, RLS tests per role, React Native Testing Library, Playwright web, Maestro or Detox mobile smoke tests.
  9. Quality gates: ESLint, Prettier, typecheck, tests, Expo Doctor, dependency scan, secret scan, production build in GitHub Actions.
  10. Observability: environment, release, user/organization pseudonymous context, request ID; never log payroll images, tokens, or sensitive message bodies.

Immediate code issues

Data correctness

loadList() silently returns seed data after parse/storage errors. Production must distinguish first run, offline cache, corruption, and server failure. Add schema migrations and visible sync health.

API security

Existing fetch adapters send no authorization header and expose endpoint URLs to clients. Add shared authenticated API client, refresh handling, timeouts, aborts, retries, and consistent error objects.

Financial safety

QuickBooks exports need idempotency and mapping tables. Payroll analyzer currently always returns 80 hours after delay. Never deploy prototype inference behind production labels.

Native permissions

Map requests user location, but release config needs complete iOS/Android location descriptions and permission behavior. Add privacy manifests/data-safety declarations for camera, photos, location, identifiers, and diagnostics.

10 · Security & compliance

Personnel, payroll, location, and operational data require real controls

Required at pilot

  • TLS everywhere; encryption at rest.
  • MFA for owner, admins, finance, and integration managers.
  • RLS and backend authorization tests for every role.
  • Short-lived signed file URLs and private buckets.
  • Append-only audit events for access changes, approvals, exports, and verification.
  • Rate limiting, invite throttling, webhook verification, dependency and secret scanning.
  • Backups with documented restore test.

Policies and legal

  • Privacy Policy, Terms of Use, acceptable-use policy, and support contact.
  • Data retention/deletion schedule by record class.
  • Account deletion request flow and company offboarding/export.
  • Marketplace/job terms, employer/seller verification, prohibited-content rules, report/block/moderation.
  • AI disclosure and required human confirmation.
  • Confirm payroll, employment, tax, public-record, and incident-record obligations with qualified counsel.

FireOps does not appear to need HIPAA by default, but it handles sensitive employee and business information. Avoid unsupported compliance claims. Obtain legal/security review based on actual customers and jurisdictions.

14 · Launch criteria

Definition of “working”

  • Two test companies cannot read, search, subscribe to, download, or infer each other’s private records.
  • Every user signs in, resets credentials, accepts invite, changes company if permitted, and loses access immediately when suspended.
  • All sensitive actions fail when permission is absent—even through direct API calls.
  • Mobile-created record appears on desktop and second device after sync; offline records retry without duplicates.
  • Every uploaded image/PDF remains available after app restart/cache clear and uses short-lived authorized URLs.
  • Chat delivers online in seconds, queues offline, sends allowed push, and records urgent acknowledgement.
  • Inspection failure creates issue and resource state transactionally with actor/time audit.
  • Payroll/OCR never auto-approves; corrected values, original file, reviewer, and approval history remain traceable.
  • QuickBooks reconnect, token refresh, webhook replay, duplicate export, and partial failure paths are tested in sandbox.
  • Crash reporting, API alerts, backups, support contact, and rollback work in production.
  • iOS and Android store reviews pass; desktop supports current Chrome, Edge, Safari, and Firefox.
