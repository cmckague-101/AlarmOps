1

Create Supabase project

Project hosts authentication, Postgres data, and file storage.

Create project

  1. Open Supabase Dashboard and create project.
  2. Choose region near pilot company.
  3. Generate strong database password and store it in password manager.
  4. Wait until project reports healthy.

Record browser-safe API values

Open Project Settings, then API. Record project URL and publishable key. Older projects may label publishable key as anon.

VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLISHABLE_KEY
Never expose service-role key.Do not place service-role key in Vercel. Never use it in any variable beginning with VITE_. Vite sends those values to every browser.
2

Apply database migrations

Migrations create company isolation, fleet storage, file policies, and owner-only vehicle controls.

Run from repository root

npx supabase login
npx supabase link --project-ref YOUR_PROJECT_REF
npx supabase db push

Approve listed migrations. Confirm command includes:

  • 202508240001_system_admin_companies.sql
  • 202508240002_fleet_state.sql
  • 202508240003_owner_vehicle_changes.sql
  • 202508240004_remove_system_admin.sql
Owner rule enforced in Postgres.Members can view fleet and report issues. Database rejects member attempts to add vehicles, edit vehicle fields, change status, or change assignment. Hiding controls in UI is not security by itself.

Connect GitHub once. Every push to main then creates production deployment.

  2. Connect GitHub account and import cmckague-101/AlarmOps.
  3. Keep root directory at repository root.
  4. Confirm framework preset is Vite.

Add environment variables

In Vercel project settings, open Environment Variables. Add both values for Production and Preview.

VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co

Configure authentication

Invitation links must return to deployed account setup route.

Open Authentication, then URL Configuration.

Lock registration

  • Disable open user registration. Pilot accounts should come from controlled invitations.
  • Require email confirmation.
  • Keep minimum password length at 10 or higher.

Configure SMTP before external invitations

Open Authentication email provider settings and add company SMTP provider. Supabase default mail service has low limits and is not suitable for real-company onboarding. Send one test invitation before pilot launch.

5

Create pilot company

Operator provisions owner and company through Supabase Dashboard.

Invite company owner

  1. In Supabase, open Authentication, then Users.
  2. Choose Add user, then Send invitation.
  3. Use owner's real email. URL Configuration sends invitation to /accept-invite.
  4. Copy owner Auth user UUID.
  5. Confirm matching UUID exists in public.profiles.

Create company and owner membership

Open SQL Editor. Replace every uppercase placeholder, then run transaction.

begin;

with new_company as (
  insert into public.companies (name, company_code, industry, owner_user_id)
  values ('COMPANY NAME', 'COMPANY-CODE', 'INDUSTRY', 'OWNER_AUTH_USER_UUID')
  returning id
)
insert into public.company_members (company_id, user_id, role)
select id, 'OWNER_AUTH_USER_UUID', 'owner'
from new_company;

commit;

Company code must be unique and contain 3 to 32 uppercase letters, numbers, or hyphens. Full procedure and verification query are in SUPABASE_SETUP.md.

Remove legacy function

If project previously deployed system admin function, delete it once.

npx supabase functions delete system-admin-companies --project-ref YOUR_PROJECT_REF
6

Add controlled crew access

Use manual membership setup until product invitation flow writes authenticated memberships.

Current pilot limitation.Crew entries created inside fleet screen are operational records only. They do not create Supabase Auth users or company memberships. Do not tell crew that in-app Send invitation control provisions login access yet.

Create crew test account

  1. In Supabase Authentication, create user with unique pilot password and confirmed email.
  2. Share password through password manager, never email or text message.
  3. Copy auth user UUID.
  4. Find pilot company UUID in Table Editor or SQL Editor.
  5. Add membership with SQL below.
insert into public.company_members (company_id, user_id, role)
values ('PILOT_COMPANY_UUID', 'CREW_AUTH_USER_UUID', 'member')
on conflict (company_id, user_id) do update set role = 'member';

Crew member can sign in, view vehicle details, report issues, and add issue updates. Only owner sees vehicle creation and editing controls. Manual passwords are for controlled pilot testing only. Build crew invitation and password-reset flows before wider release.

Remove crew access

delete from public.company_members
where company_id = 'PILOT_COMPANY_UUID'
  and user_id = 'CREW_AUTH_USER_UUID';

Delete or disable Auth user too when access should end across all companies.

7

Verify before pilot

Run each check with owner and member accounts in separate private browser windows.

  • Production URL loads without console configuration errors.
  • Company, owner profile, and owner membership match in Supabase.
  • Owner invitation opens /accept-invite and password setup completes.
  • Owner can add vehicle, edit details, change status, assign crew, and upload image or PDF.
  • Reload preserves vehicle, issue, crew, and activity data.
  • Member can view vehicle but sees no Add vehicle, Edit vehicle details, status, or assignment controls.
  • Member can open issue and add issue update.
  • Direct member attempt to change fleet_state.data.vehicles fails with "Only company owners may change vehicle details".
  • Second company cannot read first company fleet or files.
  • Sign out works on desktop and mobile browser.

Operational checks

  • Enable Supabase database backups appropriate for pilot data.
  • Review Supabase Auth and Postgres logs after first test.
  • Keep Vercel production branch restricted to main.
  • Do not use shared owner credentials. Each person gets individual account.
